# Панель управления контейнером

Интерфейс реализуется на Avalonia с C# и .NET 10. Выбран последний стабильный выпуск; проверенная версия и правило закрепления зависимостей описаны в [архитектуре](03-Windows-Architecture.md). Прикладная модель контейнера и системные операции не должны зависеть от типов UI.

## Открытие среды без запуска приложения

Основная панель поставляется как x64-приложение с SingleFile для уменьшения числа файлов. Она управляет также x86-процессами через движок, но не становится AnyCPU-механизмом виртуализации. Служба, драйвер и нативные DLL имеют собственные роли и могут находиться отдельными файлами. [Принятый состав](13-Implementation-Options.md).

Контейнер должен открываться как самостоятельный объект WinLayer. Команда «Открыть контейнер» показывает его панель и при необходимости подключает хранилище. Она не обязана запускать установленную программу или создавать отдельный рабочий стол Windows.

Панель находится вне виртуализируемого прикладного процесса и обращается к движку через проверяемый управляющий интерфейс. Это позволяет видеть состояние и останавливать приложения при их сбое. Действия открытия файлов и обслуживания выполняются внутри выбранного контейнера. Ссылки следуют выбранному маршруту, включая явно разрешённый внешний браузер; обычное закрытие панели не останавливает работающие приложения.

## Реестр контейнера

Нужен просмотрщик объединённого представления, а не только редактор файла локального куста. Пользователь должен видеть, откуда взяты ключ или значение: из основной системы, из локального слоя либо из их объединения. В расширенном режиме показываются скрытые объекты и непрозрачные ветки.

Все изменения через этот просмотрщик идут через правила движка. Изменение внешнего значения создаёт локальную версию, удаление — метку. Команда «Сбросить локальное изменение» удаляет переопределение и может снова открыть внешнее значение; это отдельное действие от удаления значения внутри среды.

Разрядные представления, `HKCU` и `HKCR` должны соответствовать выбранной виртуальной среде. Подключение `local.hiv` обычным внешним Regedit не покажет её полностью. Прямое редактирование файла куста во время его использования движком не является поддерживаемым способом управления.

Первую панель разумно начать с просмотра. Редактирование добавляется поверх тех же операций движка, а не как второй самостоятельный механизм записи.

## Программы и обслуживание

По умолчанию список показывает локально зарегистрированные приложения и локальные переопределения записей. Последние имеют отдельную отметку происхождения. Программы, видимые исключительно через нижний слой, можно показать отдельным фильтром; их наличие не должно автоматически добавлять новые записи в список Windows.

Для каждой карточки отображаются только доступные действия. «Исправить» или «Изменить» требует поддержки конкретного установщика. Панель и внешний список Windows используют один сервис обслуживания, поэтому удаление одним способом обновляет второй.

Не следует получать список через запуск потенциально обслуживающих продукт команд. Чтение каталога отделяется от выполнения установки, самовосстановления или удаления. Экземпляры одного продукта в разных контейнерах различаются по идентификатору среды и приложения.

Удаление одного приложения и удаление всего контейнера — разные операции. Первое запускает его деинсталлятор внутри среды. Второе останавливает среду, снимает публикации, освобождает хранилища и удаляет данные контейнера; запуск всех деинсталляторов для этого обычно не нужен при соблюдении контракта локальности.

## Процессы

Список строится по данным движка, а не по расположению EXE и не только по дереву потомков. Браузер с внешним EXE, запущенный внутри контейнера, должен присутствовать; обычный внешний браузер — отсутствовать. Изолированные исполнители служб тоже учитываются.

Разрешённый внешний браузер можно показывать отдельно как получателя запросов контейнера. Он не считается его процессом и не завершается при остановке среды. Входящие специальные ссылки направляются по [правилам маршрутизатора](10-External-Applications-and-Protocols.md), а не по принадлежности браузера.

Для процесса полезны имя, PID с идентичностью времени жизни, командная строка, источник EXE, способ запуска, уровень прав, загрузка CPU и память. Связь «порождено запросом контейнера» может отличаться от обычного родительства процесса, поэтому эти сведения не следует смешивать.

Можно завершить выбранный процесс или остановить все процессы контейнера. Остановка включает контролируемое ожидание и принудительное завершение при необходимости. Закрытие последнего видимого окна не доказывает завершения фоновых процессов или установки.

Общие службы хоста не выдаются за процессы контейнера и не завершаются кнопкой «Остановить всё». Если работа конкретного запроса выполняется через общий посредник, управление относится к этому запросу в пределах поддерживаемой модели.

## Размер среды

Настройки дисков различают общую ёмкость, локально занятый объём и текущий доступный рост. Для динамического режима виден способ распределения общего остатка, для фиксированного — лимит и возможный дефицит места на хосте. Запас для физического тома показывается отдельно и не складывается повторно для каждой виртуальной буквы. [Расчёт квот и исключения](12-Virtual-Disks-and-Quotas.md).

Пользователю прежде всего нужен физический объём, занимаемый локальными файлами, кустом, метаданными, кэшами и журналами. Внешние данные, лишь видимые через объединение, не входят в этот размер.

Следует различать логический размер файлов и реально выделенное место. Сжатие, разреженные файлы и жёсткие ссылки внутри локального слоя могут менять результат подсчёта; при подсчёте дискового места один и тот же файловый объект не учитывается многократно. Копии и снимки показываются отдельно, если поддерживаются.

Размер по программе часто приблизителен: несколько продуктов могут использовать общие файлы и кэши. Оценка из записи установщика не должна выдаваться за точное измерение, а сумма размеров карточек — за точный размер контейнера. Долгий подсчёт выполняется в фоне с отметкой времени результата.

## Жизненный цикл и внешние элементы

| Действие | Результат |
| --- | --- |
| Открыть панель | Просмотреть состояние и подключить среду при необходимости |
| Запустить приложение | Выполнить выбранное действие с контекстом среды |
| Закрыть панель | Оставить приложения работающими |
| Остановить контейнер | Завершить его работу и дождаться освобождения ресурсов |
| Отключить интеграцию | Убрать управляемые ярлыки и записи Windows, сохранив среду |
| Подключить перенесённую папку | Привязать среду к новому физическому пути и восстановить публикации |
| Создать независимую копию | Назначить новый идентификатор и отдельные публикации |
| Удалить контейнер | После остановки снять интеграцию и удалить его данные |

Временная недоступность папки и повреждение хранилища показываются явно. Они не должны вызывать автоматическое удаление всех сведений о среде. Ожидание перезагрузки или продолжающаяся установка учитывается при остановке и переносе.

## Первая версия панели

Для браузера сначала показывается режим: обычный внешний либо изолированный. Внешний использует настоящий профиль и загрузки хоста; панель не предлагает их сброс как данные контейнера. Для изолированного показываются выбранный источник профиля, режим его использования, дата получения основы и состояние текущего сеанса. Режим постоянной копии сохраняет локальные данные между запусками. Режим свежей основы получает их извне перед новым сеансом и не переносит изменения предыдущего сеанса; это последствие явно отражается в настройке. Открытие дополнительной ссылки в уже работающем экземпляре профиль не обновляет. Панель позволяет увидеть фоновые процессы, мешающие завершению сеанса, и выполнить управляемый перезапуск. Она не должна обещать перенос всех авторизаций только по факту успешного копирования файлов.

Для специальных схем показываются назначенные приложения и контейнеры, наличие внешнего обработчика и состояние публикации в Windows. Диагностика ожидающего входа не раскрывает коды и токены. Удаление контейнера убирает его маршруты, сохраняя маршруты остальных сред и актуальный пользовательский выбор.

Сначала нужны обзор, список программ с поддерживаемыми действиями, процессы с остановкой, размер, список публикаций и просмотр реестра. Расширенное редактирование реестра, подробный мониторинг производительности и полноценный файловый менеджер могут добавляться позже.

По сложности такая панель в основном представляет обычное прикладное ПО. Трудная часть — получить достоверные данные движка и использовать для действий тот же контекст изоляции. Копирование внешнего «Диспетчера задач» или «Программ и компонентов» без контейнерного интерфейса этого не обеспечивает.
