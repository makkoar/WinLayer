# WinLayer

WinLayer — рабочее название проекта среды для установки и запуска Windows-приложений в одной папке. Установщики и обновления должны сохранять там свои файлы и реестр, включая данные, которые обычно принудительно попадают на системный диск. Недостающие данные читаются из основной системы для совместимости. Контекст среды распространяется на запускаемые процессы.

Снаружи доступны управляемые ярлыки и записи в списке программ Windows. Запуск и обслуживание выполняются через WinLayer с контекстом контейнера. Для веб-ссылок рассматривается явное исключение: обычный внешний браузер со своим профилем, а специальные ссылки возвращаются к нужному контейнерному обработчику через маршрутизатор. Сам контейнер открывается в отдельной панели с программами, реестром, процессами и сведениями о занимаемом месте.

Стадия проекта: первый диагностический прототип. Созданы управляемая служба, панель Avalonia, CLI и общий протокол; драйвер x64 и DLL x86/x64 собраны в Debug и Release. Файловая и реестровая виртуализация ещё не реализованы; подпись и загрузка драйвера требуют проверки на стенде. [Устройство и запуск прототипа](Docs/14-Prototype.md).

[План задач](https://github.com/makkoar/WinLayer/issues/15) · [Правила для контрибьюторов](CONTRIBUTING.md)

Выбран стек разработки: C#, .NET 10 и Avalonia последней стабильной версии. На 31 октября 2026 года проверена Avalonia 12.1.4; при создании проекта версия перепроверяется и закрепляется конкретным номером. Выбран собственный гибридный движок: драйвер файлов/реестра, нативные DLL x86/x64 и управляющая служба. Основное приложение — x64 с публикацией SingleFile; нативные файлы рядом допустимы. Целевая ОС — Windows 11, минимальная цель совместимости — Windows 10 22H2 x64 всех редакций. [Архитектура](Docs/03-Windows-Architecture.md), [принятые решения и первый прототип](Docs/13-Implementation-Options.md).

Рабочие каталоги задаются исключениями в конфигурации контейнера. Нужен быстрый запуск EXE, BAT и других поддержанных файлов из контекстного меню Проводника. Первый прототип проверяется на простом ПО, затем сценарии усложняются.

Базовая идея реализуема. Её основа — виртуализация файлов и реестра с копированием при изменении. Целевой сложный пример — Visual Studio с установщиком, обновлениями и SDK. Совместимость с ним требует проверки: службы установки и системные компоненты выходят за пределы обычного дерева дочерних процессов. Переносимость повышается, но зависит от внешних компонентов, пользователя и версии Windows.

Принятое условие: среды подготавливаются на чистой Windows. Обнаружение ранее установленных зависимостей и автоматический сбор пропущенных компонентов не входят в требования первой версии.
